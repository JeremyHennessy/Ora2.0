## The authored possibility witness

The nine-slot, 27-word candidate preserves the supplied founder's length:

```text
0 CONST    r1 = 1
1 FORAGE   port = r0
2 FEEDBACK r1
3 IFZERO   r1 -> 7
4 COPY
5 DIVIDE
6 JUMP     1
7 CONST    r1 = 1
8 XOR      r0,r1       # wraps to 0
```

This is ordinary win-stay/lose-shift. On a nonempty attempted food packet with truthful feedback and an unchanged target, keep the successful port; otherwise flip it. All four Boolean port/target rows give the target as the next port. These are abstract identities plus independently inspected correspondence between the declared paths and source dispatches, **not machine-verified VM histories**.

Feedback zero also means no food was present. A failed empty-site attempt therefore does not identify the other port as correct. Existing packet targets change at the global tick-64 boundary, can vary across packets, and renewed targets change again at tick 2048. Consequently repeated truthful stable-target opportunities cannot be assumed for an actual mutant.

The retained port register is acquired private state under the conditional premise. The program is stationary and cannot implement the earlier proposed older-site memory task after visiting another site. It has no acquired-code inheritance mechanism: newborns have blank registers and would have to reacquire the port. Inherited learning code, inherited fixed answers and inheritance of acquired experience remain separate claims.
